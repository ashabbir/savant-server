## Changes

### Knowledge Graph Automation

- Replaced direct scheduled maintenance execution with durable "contemplate" jobs handled by the normal background worker. Runs every four hours or on demand; failed reconciliation marks the job failed.
- Adds similarity-based duplicate consolidation: normalized exact title/content matches or embedding cosine similarity strictly above the configurable threshold, default 0.70.
- Matches require the same node type and identical non-empty domain names; domains without the configurable threshold are never automatically merged.
- Selects up to 200 seeds, newest first; insights and domains are excluded as seeds. Using 20 nearest same-type nodes plus directly connected neighbors; insights may participate as related candidates.
- Caps merge/delete involvement at 100 nodes per run. Remaining candidates wait for subsequent runs; more than spanning more jobs.
- Caches embeddings by model/text identity and tracks per-node fingerprint covering node content, incident relationships, action reasons, similarity scores, matching configuration, and SHA-256 integrity.
- Adds suppression/contradiction metadata bypasses similarity when it still requires compatible type/scope.
- Merges combine provenance, preserve metadata provenance, and rewrite still required compatible type/scope.
- Expired knowledge is marked inactive; self-referencing edges are removed.
- Remaining staged nodes are published even when outside the selected batch; deferred reviews remain retryable; policy/threshold changes trigger re-review.

### Maintenance Visibility and Recovery

- Added paginated run history with total counts, page number, and page size.
- Added downloadable per-run JSON reports containing before/after runs, affected relationships, action reasons, similarity scores, matching configuration, and SHA-256 integrity.
- Failed transactions report separately from attempted operations.
- Reports support privileged, transaction-based download without a revert endpoint. Restoration must reject conflicting later edits or relationships; already-restored reports are no-ops.
- Added persistent tables for reports, review progress, and embedding cache; plus job identity on maintenance runs.

### Domain Permissions and Knowledge Contributions

- Removed the admin-only restriction from knowledge storage: non-admin users can contribute within assigned writable domains.
- Explicit connections are inspected for established role-based access; attempts to assign beyond owned domains are rejected.
- When domain connections are omitted, non-admin contributions link to existing domains.
- Added mcp/users/me/domains and the my_domains MCP tool, returning assignments, write permissions, and per-domain role-specific instructions.
- Permission-denial messages now identify the domain that before mutations. Domain creation remains admin-only; newly created domains receive read-only assignments for active non-admins.
- Updated MCP tools: domain-scoped creation and editing require write permissions; write permissions and per-domain role-specific instructions.
- Added a lightweight graph-summary response that returns totals and type counts without full node/edge inventories.

### User Analytics

- Added admin leaderboard: knowledge additions earn 10 points; research/lookups earn 5; searches earn 2. The requested window defaults to seven days and is bounded to 1–365.
- Added per-user topic-model endpoints and topic information with recency, topics, and topic labels, weighted keywords, examples, search-versus-contribution comparisons, and activity summaries.
- Topic analysis combines MCP query text and authored knowledge, producing topic labels, weighted keywords, examples, search-versus-contribution comparisons, and activity summaries.
- Important limitation: empty-window queries return zero; profile stats/statistics, logins, and user activity summaries are returned with data present.
- MCP usage logging now captures persona or asset identifiers when ordinary query text is absent.

### Semantic Indexing and Search

- Separated semantic indexing from structural AST/AST lifecycles; semantic rebuilds and pruning no longer delete independently managed structural artifacts.
- Added semantic-specific source timestamps, recorded only after successful semantic indexing; no longer incorrectly mark semantic content appear current.
- Excluded conventional test/source paths, generated directories/files, and generated-header content from semantic indexing while preserving structural coverage.
- Added binary/MAL-content rejection.
- Fixed filtered vector retrieval by ranking materialized filtered candidates, avoiding missing small-repo results caused by approximate-index filtering.
- Fixed batching issue due to return returned IDs across every insertion page, preserving vectors for all chunks.

### Parser and Worker Reliability

- Isolated native Markdown parsing in a subprocess with a 30-second timeout, preventing scanner crashes from terminating the main worker.
- On parser failure, preserves existing source with a marker flag and returns the source with a single dump in the parser subprocess.
- Skips Markdown declaration-AST extraction and preserves existing "indexed" repository state.
- Added SAVANT_WORKER_SCHEDULER_ENABLED=0 to stop automatic repository/graph schedulers while keeping queued-job consumption active.

### Startup and App Compatibility

- Startup user seeding now leaves existing users unchanged instead of overwriting names, roles, or activation state.
- Added SAVANT_SEED_LEG_USER=0 to omit default user creation.
- Fixed startup crash caused by the duplicate key in either supported application header. API-key authentication and role enforcement remain unchanged.
- Release documentation and VERSION advanced from 20.4.0 to 21.0.0.
